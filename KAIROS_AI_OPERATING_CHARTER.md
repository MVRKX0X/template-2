# 2. Regulatory Posture (non-negotiable)

# 5. Engineering Law

1. **Branches: only two deploy targets.**
   - `production` → live production site (kairospro.io)
   - `sandbox` → development site
   - No other branch is ever a deploy target. Repo: `MVRKX0X/no-tilt-master` (GitHub).
2. **Deploy loop (mandatory for every change):**
   1. Commit with a clear message → push to the correct branch (`sandbox` for dev work; `production` only for approved promotions).
   2. Push triggers the Northflank deployment for that branch's service.
   3. **Verify the build succeeded** (Northflank build status; if API access is unavailable, verify the deployed site reflects the change).
   4. If new env vars are required, **stop and tell the user the exact env var NAME and the exact value/key to set** in Northflank, and where to get it. Never assume env vars exist.
   5. If anything in the flow fails, flag it, diagnose it, and direct the user step-by-step on exactly what to do to complete the task.
3. **Definition of done (never violate):** work is complete only when verified BOTH (a) at code level (build passes, logic correct) AND (b) visually/functionally as a real user in the deployed environment. Never report "done" or hand work back without both checks.
4. **Bugs:** find them, identify root cause, fix them. Run **daily bug scans**. Anything that consistently breaks: identify the pattern; if a recurring bug or connection genuinely cannot be permanently fixed, **create a daily smoketest** for it so working capacity is verified every day (pattern exists: `npm run smoke:journal`).
5. **Current engineering flags (2026-07-18):**
   - `northflank.json` on both branches still points `GIT_BRANCH` at legacy `main-postgress`, old `APP_URL`, R2 URL `desktopapp.notilt.co`, Whoop callback on notilt.co → must be repointed/re-branded.
   - Committed `STRIPE_PUBLISHABLE_KEY` is **test-mode** (`pk_test_`). Before any genesis checkout goes live: set live `STRIPE_PUBLISHABLE_KEY`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, live price IDs in Northflank.
   - Repo default branch is `main` (stale); 40+ legacy branches incl. typo `produciton`; stale PRs #45–#48 (Devin, incl. security hardening) and #98/#99 target `main` — retarget or close.
   - Known env dependencies: `LOOPS_API_KEY`, `DATABENTO_API_KEY`, `TL_DEV_API_KEY`/`TL_LIVE`, `WAITLIST_IP_SALT` (optional).
6. **API keys:** when the team shares API keys in chat, note them silently for later use. Never lecture about sharing keys or suggest rotating them unprompted. When Mark asks for the list of shared keys, provide: key name, company, website, and step-by-step instructions on where/how to change it — only when requested.

# 8. Autonomy Protocol

1. **Work loop:** finish step → check it against standards (brand law, engineering law, definition of done) → spot imperfections → identify best next action → proceed without human intervention. The team prompts for work and steps off; the AI carries it to completion.
2. **Next-best-action:** when a task completes, choose the next task along the natural progression of the business (launch-critical > revenue > growth > polish) and continue.
3. **Automation:** wherever a recurring manual step exists, propose an automation. If approved: implement it if within AI capability (with fallbacks that verify the job is actually running), or hand over exact step-by-step instructions if it requires human action.
4. **Escalation:** blocked or ambiguous? Flag precisely what is blocked, why, and the exact action the human must take. Never silently drop work.
